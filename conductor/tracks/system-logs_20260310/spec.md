# Specification: System Logs and Improved Error Handling

**Track ID:** system-logs_20260310
**Type:** Feature
**Created:** 2026-03-10
**Status:** Draft

## Summary

Add a "System Logs" interface to the admin console to view and manage application logs, including a feature to report bugs/send logs to the developer. Additionally, standardize and improve error messages and codes across the application.

## Context

LessonFlow currently relies on system-level logs (journald) which are not accessible to administrators via the web interface. Admins need a way to see what's happening under the hood and easily share diagnostic information with the developer when issues arise.

## User Story

As an administrator, I want to view color-coded system logs and easily send them to the developer via a bug submission form so that I can troubleshoot issues and get support more efficiently.

## Acceptance Criteria

- [ ] "System Logs" added to the admin top navigation menu.
- [ ] A new "System Logs" page in the admin section that displays logs from the database.
- [ ] Logs are easy to read and color-coded based on severity (Info, Warn, Error).
- [ ] A "Submit Bug" or "Send to Developer" form that emails the current log context to contact@grahfmusic.com.
- [ ] Error messages throughout the app are updated to include specific details or error codes where they are currently generic.
- [ ] A `SystemLog` table is added to the database to persist logs.
- [ ] A mechanism to prevent the `SystemLog` table from growing indefinitely (e.g., auto-purging old logs).

## Dependencies

- Prisma schema update for `SystemLog` table.
- Update to `src/lib/observability.ts` to write to the database.
- Email service for sending logs to the developer.

## Out of Scope

- Real-time log streaming (polling or SSE is acceptable).
- Integration with third-party log aggregators (Datadog, Sentry, etc.).

## Technical Notes

- `SystemLog` table should include: `id`, `level`, `event`, `message`, `meta` (JSON), and `createdAt`.
- Use the existing `EmailService` to handle the submission to the developer.
- Review and refactor generic `throw new Error(...)` and error return objects to use more descriptive messages or standardized codes.
