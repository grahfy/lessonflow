# Invoicing and Payments

<div class="manual-callout success">
<strong>Billing rule:</strong> Invoices are safest when you respect their lifecycle. A draft is not sent. A sent invoice is no longer just internal work. A paid invoice changes reporting.
</div>

This chapter covers invoice creation, editing, sending, reminders, payment-state updates, and credit-note handling.

## What you can do in the invoices area

- search and filter invoices
- create standalone invoices
- create invoices from bookings
- use product presets
- edit line items and due dates
- save drafts
- send or resend invoices
- download PDFs
- mark paid or unpaid when allowed
- void when appropriate
- send overdue reminders
- issue credit notes

## Invoice list and filters

Use the main invoice list to review:

- current status
- outstanding balances
- overdue items
- aging-based follow-up candidates

This view is the fastest place to identify unpaid work needing action.

## Creating an invoice

Use `Create New Invoice` when billing does not need to begin from the bookings screen.

LessonFlow supports:

- lesson-based billing
- standalone manual line items
- preset-based item creation

Choose the basis that matches the work being billed. If the invoice should stay tied to a lesson, create it from the booking whenever practical.

## Draft vs create-and-send

Use `Save Draft` when:

- the invoice still needs review
- line items are incomplete
- the customer details need confirmation

Use `Create & Send` when the invoice is ready to leave the system immediately.

## Editing invoice details

Review these areas before sending:

- customer name and contact details
- due date
- line item descriptions
- unit prices and quantities
- tax mode
- payment terms

## Payment lifecycle actions

Not every action is available at every stage.

| Status | Typical actions |
| --- | --- |
| Draft | Edit, save, send, delete if still safe |
| Sent | Resend, remind, mark paid, void |
| Paid | Mark unpaid if correction is needed, review history |
| Voided | Review only unless correction requires a different accounting path |

<div class="manual-callout warning">
<strong>Do not use deletion as a substitute for correction.</strong> If an invoice has already been sent or paid, use the safer lifecycle path such as voiding or issuing a credit note.
</div>

## Reminders and overdue follow-up

Use reminders only for overdue sent invoices. Outstanding and aging filters help you find the correct candidates.

Manual reminder actions should be used when:

- the invoice is overdue
- the student or parent genuinely needs a follow-up
- you have confirmed the invoice should still be collected

## Credit notes

Use a credit note when the original invoice needs a formal negative correction. This is the correct path when sent or paid billing needs a structured reversal instead of an informal deletion.

## Quick billing checklist

1. Confirm the customer details are correct.
2. Confirm the due date and tax mode.
3. Review the line items.
4. Send only when the invoice is ready.
5. Use reminders and payment-state actions deliberately.
